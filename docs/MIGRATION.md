# Migration and recovery

Version 0.22 retains the 0.21 schema-5 database, signed-message fields, HMAC bytes, configuration commitments and authorization rules. Stop older workers and SQLite connections, back up the correct database and reopen intact state with `Store(path)`. With unchanged policy and credentials, compatibility does not require schema migration or configuration reactivation. Eligible decisions, pending reviews, nonce history and optional checkpoints retain their original checks. The added environment, worked-example and reproduction commands do not change authorization rules, message formats or database schema.

`Store.activate_configuration` requires exactly 64 ASCII hexadecimal characters for the digest. Uppercase and mixed-case values remain accepted and normalize to lowercase. Whitespace, non-hexadecimal characters, incorrect lengths and non-string values raise `ValueError` before clock invocation or a configuration transaction. This preflight failure leaves the active digest, generation, key rows, decisions, high-water mark and audit chain unchanged. It differs from credential-reuse rejection, which occurs after a valid time reading and can commit that reading and a rejection event.

Versions earlier than 0.21 accepted some 64-character strings that decoded to fewer than 32 bytes because `bytes.fromhex` permits ASCII whitespace. Such a low-level activation could advance the generation and leave configured gate or evidence workers inactive. The fix prevents future malformed calls and does not repair an already stored invalid digest. A valid audit chain can still contain that earlier activation; `verify-audit` is an audit-chain check, not a configuration-health check.

If affected state is present, stop workers and assess the intended policy and credentials, then activate the appropriate `Gate` or `EvidenceIngestor` through its high-level method. That object computes its configuration digest. Reactivation advances a generation; construct other workers afterward, review invalidated decisions and refresh source-derived evidence where required. Do not trim, pad or guess an intended digest. A syntactically valid low-level digest still requires correct trusted administration.

The read-only audit-file API and CLI retain their explicit `audit_chain_only` scope. They do not validate other application tables, pin identity between invocations, install worker guards or repair state. Independently retained checkpoints and exact heads remain optional caller-supplied anchors. Existing diagnostic failure codes and CLI exit behavior are unchanged.

The model adapter retains its HTTP 200 and top-level-error contract. Approval integer bounds, replay retention, state binding and conditional clock persistence remain in place. Storage or commit failures can prevent records from persisting, and lost clock observations or replay rows cannot be reconstructed. Stop workers and connections before recovery; assess independent evidence, outstanding messages, clocks and credentials. Do not lower time marks or erase replay history to force retries. The toolkit remains a local research simulator with no physical-device actuator.
